# EvidenceShift

I built EvidenceShift to examine whether document-grounded answers remain
supported when evidence order changes. I compare local models, inspect their
citations and abstentions, and retain the source passages and failed outputs
alongside the results. The project includes semantic document retrieval and
an experimental local evidence viewer.

**Status: experimental evaluation project.** The latest confirmation exposed
false abstentions and a cited arithmetic error. Valid citation IDs and exact
copied quotations do not establish a correct or complete answer.

## What is implemented

| Path | Purpose | Inference | Evidence |
|---|---|---|---|
| `web_demo/local_app_v21.py` | Local upload and source-excerpt viewer | Ollama, Qwen 3 8B | Shared MiniLM / Chroma, with full small-corpus coverage or semantic hits plus neighbors |
| `run_direct_answer_baseline.py` | Direct-answer comparison of three models | Local Qwen 3 4B, Qwen 3 8B, Gemma 3 4B | Fixed saved story passages; no new search |
| `run_direct_confirmation.py` | Frozen direct Qwen 8B reserved-case confirmation | Local Qwen 3 8B | Eight fictional cases, each in two passage orders |
| `compare_evidence_models.py` | Compare passage and text-unit ID selection | Same three local models | Fixed saved story passages; no new search |
| `src/evidence_api/app.py` | Original document and prompt-comparison API | Ollama; default Qwen 3 4B | Shared MiniLM / Chroma |
| `web_demo/app.py` | Earlier cloud-provider prototype | Groq | Shared semantic retrieval; hosted behavior unvalidated |

The viewer copies source spans selected by a model. It does not use the direct
answer runner. Original generation and critic revisions remain available for
reproducibility; they are not automatic factual approval services.

## Start the local viewer

Use Python 3.12 and the existing activated project environment. If this is a
fresh checkout, create `.venv` and install dependencies first:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test,local]'
```

Existing environments can install missing dependencies with the same command;
do not upgrade an evaluated environment before preserving its package record.
Keep Ollama running with `qwen3:8b` installed, then start:

```bash
python -m streamlit run web_demo/local_app_v21.py
```

The Streamlit terminal prints the local URL. Upload PDF, DOCX, TXT or MD files,
process them, then ask a question or inspect search results. The sidebar offers
`retrieved`, `reversed` and `no_context`. This UI's no-context option is a
**zero-model-call code control**, not successful model abstention.

Source bytes, questions, context, output and traces save under
`results/local_upload_session_*`. Use **Prepare complete session export** to
download the complete workspace. Clearing the workspace removes its temporary
index; saved session files remain. Text PDFs only; OCR is not implemented.

## Recorded findings

My frozen direct Qwen 8B confirmation contains 16 completed model calls:

| Source-based outcome | Trials |
|---|---:|
| Clean supported answers or justified abstentions | 9 |
| Supported answers with minor caveats | 2 |
| Correct core followed by false abstention | 4 |
| Material arithmetic error | 1 |

All citation IDs exist. For five kits, first two free, four credits per
additional kit, one order returned the correct **12**, the reversed order
returned **8**. Both cited the relevant passage. One separate no-context record
was generated by code and is excluded from the 16 model outcomes.

These are paired trial counts from eight short reserved fictional questions,
not a general accuracy estimate. The cases were reserved before selection but
are not independently held out. I manually verified the saved assessments
against the cited source passages. The review records identify me as the
project reviewer. This verification concerns the recorded cases; it does not
establish reliability on arbitrary documents.

See [results](results/published/README.md), [methodology](docs/METHODOLOGY.md),
[known failures](docs/KNOWN_FAILURES.md), and
[reproduction](docs/REPRODUCIBILITY.md). Reading saved results needs no model run.

## Software checks

```bash
python scripts/check_repository.py
PYTHONPATH=src:. python -m pytest -q tests
python compare_evidence_models.py --self-test
python run_direct_answer_baseline.py --self-test
python run_direct_confirmation.py --self-test
```

These are integrity and controlled software checks. They do not measure live
factual accuracy. The dependency ranges are install requirements, not an exact
environment lock. Historical runs retain their own available provenance.

## Repository map

| Location | Contents |
|---|---|
| `src/evidence_api/` | Parsers, document store, API, preserved generation revisions |
| `web_demo/` | Local viewer revisions and earlier cloud prototype |
| `evaluation/` | Fixed fixtures, replay and ingestion/retrieval runners |
| `tests/` | Controlled contract and integration tests |
| `docs/` | Current architecture, methodology, reproduction, limitations, history |
| `results/published/` | Selected assessments and frozen raw records with hashes |
| `results/reviews/` and other local result folders | Original local evidence; retained and ignored by Git |
| `references/` | Research bibliography and document provenance |

[Architecture](docs/ARCHITECTURE.md) documents the distinct execution paths.
[Experiment history](docs/EXPERIMENT_HISTORY.md) records revisions without
combining incomparable denominators. Older installer guides describe their
own revision; use this README for current entry points.

I have not validated a public deployment. Any hosted version must retain semantic
retrieval; there is no TF-IDF fallback. A cloud inference model would require
separate evaluation and must not be described as the local Ollama model.
See [release status](docs/RELEASE_GATES.md) and [publication plan](docs/REPOSITORY_PLAN.md).
